# Платформа — мобильное приложение спортивного клуба

Android-приложение для клуба «Платформа» (Ижевск): клубная карта на турникет,
расписание групповых занятий с записью, покупка абонементов и баланс.
Написано на Kotlin + Jetpack Compose.

Концепция повторяет привычную логику фитнес-приложений (вход по телефону, карта
в центре нижнего меню, запись в расписании, тарифы, баланс), но интерфейс, тексты,
структура и фирменный стиль — собственные: тёмный графит, красный акцент и знак
из ромбов, снятый с логотипа клуба.

---

## Как открыть

1. Android Studio → **Open** → выбрать папку `PlatformaSport`.
2. Дождаться Gradle Sync (скачает зависимости, нужен интернет).
3. Run на устройстве или эмуляторе с Android 8.0 (API 26) и выше.

Wrapper-скрипты (`gradlew`) в архив не вошли — Android Studio создаст их сама
при первом Sync. Если собираете из консоли, сначала выполните `gradle wrapper`.

**Версии:** AGP 8.7.2, Kotlin 2.0.21, compileSdk 35, minSdk 26, Compose BOM 2024.10.01.

## Демо-режим

Внешней системы клуба пока нет, поэтому её роль играет заглушка
`FakeCrmApi` — она живёт в памяти и имитирует задержки сети.

| Телефон | Что показывает |
|---|---|
| `+7 (912) 345-67-89` | Клиент с действующим абонементом «Базовая+» (осталось 74 дня), баланс 1 250 ₽ |
| `+7 (900) 000-00-00` | Сотрудник клуба — сразу доступен режим администратора |
| Любой другой номер | Новый клиент: анкета → выпуск карты → абонемента нет, предлагается купить |

Код подтверждения из SMS — **1111**.

Режим администратора можно включить и вручную: **Профиль → Режим администратора**.

## Что уже работает

**Вход и профиль**
- Вход по номеру телефона с кодом из SMS, таймер повторной отправки.
- Если номера нет в базе клуба — короткая анкета и выпуск карты.
- Профиль: данные клиента, номер карты, статус абонемента, баланс, выход.

**Клубная карта**
- Отдельная вкладка в центре нижнего меню — то, ради чего приложение открывают у турникета.
- Штрихкод Code 128 и QR по номеру карты (генерируются офлайн, ZXing).
- Экран автоматически поднимает яркость на максимум, пока карта открыта.
- Номер карты, владелец, тариф, статус, **дата окончания абонемента**, заморозка, гостевые визиты.

**Абонементы и деньги**
- Полный прайс из 12 тарифов, переключатель срока 1 / 3 / 6 / 12 месяцев,
  цена за весь период и за месяц.
- Оформление: расчёт новой даты окончания, оплата с баланса или банковской картой,
  поле промокода, экран результата.
- Пополнение баланса: быстрые суммы и произвольная, история операций.

**Расписание**
- Лента дней на три недели вперёд, фильтр по направлениям, карточки занятий
  с тренером, залом, длительностью и заполненностью.
- Запись и отмена записи, учёт свободных мест, экран «Мои записи».
- Запись доступна только при активном абонементе — иначе подсказка оформить тариф.

**Администрирование расписания**
- Доступно клиентам с признаком администратора.
- Ручное добавление, редактирование и удаление занятий.
- Загрузка сетки текстом (CSV) — по строке на занятие, с проверкой формата
  и режимом «заменить занятия в этих днях».
- Кнопка возврата к типовой недельной сетке.

Формат строки импорта:

```
дата;время;название;категория;тренер;зал;минуты;мест
2026-09-21;18:30;Сайкл 45;CYCLE;Дарья Котова;Сайкл-зал;45;22
```

Категории: `STRENGTH`, `CARDIO`, `CYCLE`, `MIND`, `DANCE`, `WATER`, `FIGHT`, `KIDS`.
Разделитель — `;` или `,`, строки с `#` игнорируются. Кнопка «Вставить пример»
подставляет готовый шаблон.

## Структура проекта

```
app/src/main/java/ru/platformasport/club/
├── PlatformaApplication.kt      контейнер зависимостей (AppContainer)
├── MainActivity.kt
├── data/
│   ├── model/                   доменные модели + сериализаторы дат
│   ├── TariffCatalog.kt         прайс клуба
│   ├── remote/
│   │   ├── ExternalCrmApi.kt    ← граница с системой клуба
│   │   └── FakeCrmApi.kt        заглушка на время разработки
│   ├── local/AppPreferences.kt  DataStore: сессия, расписание, записи
│   └── repository/              SessionRepository, ScheduleRepository
├── ui/
│   ├── theme/                   палитра, типографика
│   ├── components/              знак клуба, кнопки, чипы, штрихкод
│   ├── navigation/              маршруты, нижнее меню
│   ├── auth/ home/ card/ schedule/ tariffs/ balance/ profile/
│   └── AppViewModel.kt          общее состояние экранов
└── util/Format.kt               деньги, даты, склонения, телефон
```

Архитектура простая и намеренно без DI-фреймворка: репозитории отдают
`StateFlow`, экраны читают их через одну `AppViewModel`, зависимости
собираются в `AppContainer`. Для приложения такого размера этого достаточно,
а точки расширения оставлены там, где они реально понадобятся.

## Как подключить настоящую систему клуба

Всё общение с внешней системой идёт через один интерфейс —
`data/remote/ExternalCrmApi.kt`:

```kotlin
interface ExternalCrmApi {
    suspend fun requestSmsCode(phone: String): Result<Unit>
    suspend fun verifyCode(phone: String, code: String): Result<CrmAccount?>
    suspend fun register(phone: String, firstName: String, lastName: String, email: String): Result<CrmAccount>
    suspend fun fetchCard(cardNumber: String): Result<ClubCard>
    suspend fun extendMembership(cardNumber: String, tariffId: String, tariffTitle: String, months: Int): Result<ClubCard>
    suspend fun freeze(cardNumber: String, days: Int): Result<ClubCard>
    suspend fun unfreeze(cardNumber: String): Result<ClubCard>
}
```

Порядок подключения:

1. Написать `RetrofitCrmApi : ExternalCrmApi` (плюс DTO и маппинг в модели из `data/model`).
2. В `AppContainer` заменить одну строку: `val crm: ExternalCrmApi = RetrofitCrmApi(...)`.
3. Экраны, репозитории и модели менять не нужно.

Так же заменяется и источник прайса: сейчас это `TariffCatalog`, вместо него
подставляется загрузка списка `Tariff` с сервера — структура модели та же.
Для расписания в `ScheduleRepository` уже есть метод `replaceAll(events)`,
на который можно завести синхронизацию.

## Что стоит доработать перед релизом

- Настоящая оплата (эквайринг) вместо демонстрационного списания с баланса.
- Push-уведомления: напоминание о занятии, окончание абонемента.
- Вынести строки в `strings.xml`, если планируется вторая локаль.
- Тесты на репозитории и парсер импорта расписания.
- Фирменный шрифт вместо системного sans-serif (сейчас стиль держится
  на начертании, разрядке и цвете).
- Загрузка расписания файлом через системный выбор файла — сейчас текстом.
